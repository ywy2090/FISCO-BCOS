## Step 2 — EIP-7702 preCheck（inventory #7, preCheck 半部）

### FB 实现（`OpStackPreCheck.cpp:62–96`）

| 规则 | FB | op-geth `preCheck` |
|------|----|--------------------|
| Sender EOA 或 delegation code | `get_code(sender)` + `parseDelegationTarget` | `ParseDelegation` + `ErrSenderNoEOA`（`:391–396`） |
| `gasFeeCap >= gasTipCap`, `>= baseFee` | ✅ | ✅ `:411–420` |
| Auth list + CREATE | `!authorizations.empty() && CREATE` → Malformed | `SetCodeAuthorizations != nil && To==nil` → `ErrSetCodeTxCreate`（`:459–461`） |
| Present but empty auth list | `authorizationListPresent && empty` → Malformed | `len==0` → `ErrEmptyAuthList`（`:463–464`） |
| Deposit 跳过上述 | ✅ | ✅ |

**判定：✅** — 已实现规则与 op-geth 语义对齐（status 映射为 `Malformed` 可接受）。

## Step 3 — EIP-7702 intrinsic gas（inventory #7, intrinsic 半部）

### FB（`OpStackExecuteViaHost.cpp:23–36`）

```cpp
constexpr uint64_t TX_AUTH_TUPLE_GAS = 12'500;
// ...
return base + authTuples * TX_AUTH_TUPLE_GAS;  // authTuples = authorizations.size()
```

- `base` = `computeTxIntrinsicGas(...).preExecutionDebit()`（21000 + calldata + access list + CREATE term）
- 在 `executeEntryChecks` 中：`gasLimit < intrinsic` → `OutOfGasLimit`

### op-geth（`IntrinsicGas` + `innerExecute`）

```go
if authList != nil {
    gas += uint64(len(authList)) * params.CallNewAccountGas  // 25_000 per tuple
}
// applyAuthorization: if Exist(authority) → AddRefund(CallNewAccountGas - TxAuthTupleGas)
```

| 场景 | op-geth 净 intrinsic / auth | FB | 一致 |
|------|----------------------------|-----|------|
| authority **已存在** | 25000 − 12500 refund = **12500** | 12500 | ✅ |
| authority **不存在**（新账户） | **25000**（无 refund） | 12500 | 🔴 **少扣 12500/元组** |
| 无 auth list | 0 | 0 | ✅ |

**设计文档偏差：** isthmus-design §5.10 L311 写「each auth tuple adds `TxAuthTupleGas` (12500)」——简化表述；**op-geth 实际按 `CallNewAccountGas` 预扣 + 存在性 refund**（`state_transition.go:121–123`, `:795`）。

**判定：🔴** — 对新 authority 账户 undercharge；与 op-geth 共识不一致。

### 常量重复

`TX_AUTH_TUPLE_GAS = 12'500` 在 `Eip7702.cpp:9` 与 `OpStackExecuteViaHost.cpp:23` 各定义一份（apply refund 用前者）。建议提取共享常量（非本 Task 阻断）。

### 测试缺口

- 无 intrinsic OOG 用例（auth 元组数 × gas）
- 无「新 authority 账户应扣 25000 净 gas」对照测试
- `OpStack7702ExecuteViaHostPropagationTest` 用 `skipTransactionChecks=true`，不经 full entry intrinsic 路径

## Step 6 — EIP-4844 buyGas / 余额编排（inventory #13, orchestration 主体）

### 设计 MUST（isthmus-design §7.2 B10, AC #12）

| Step | op-geth `buyGas` | FB `OpStackTxExecutor::buyGas` |
|------|------------------|--------------------------------|
| `mgval += blobGasUsed × BlobBaseFee` | ✅ `:326–328` | ❌ **缺失** |
| `balanceCheck += blobGasUsed × BlobGasFeeCap` | ✅ `:321–324` | ❌ **缺失** |
| `blobGasUsed = len(hashes) × 131072` | `blobGasUsed()` `:861–863` | ❌ 无计算 |

`OpStackTxExecutor.cpp:67–73` 仅：`gasLimit×effectiveGasPrice` + L1 + operator + value；**无 blob 项**。

### Tx 字段传播（executor 层）

| 字段 | `OpStackExecuteViaHostInput` | 谁赋值 |
|------|------------------------------|--------|
| `blobVersionedHashes` | 有 | **仅测试手填**；`fillWeb3Fields` 不解码 type `0x03` |
| `blobGasFeeCap` | 有 | **未赋值**；`OpStackTransactionExecutorImpl` 未从 protocol tx 映射 |
| `blockInfo.blobBaseFee` | 有 | ✅ `resolveOpStackBlobBaseFee` ← L1Block storage |

**判定：🔴** — preCheck 可手动触发，但生产路径无法到达；buyGas 完全不扣 blob 费 → 4844 blob tx 无法共识对齐。

### 与 ETH reference 边界

Task 3 已裁定 ETH `executeViaEth` blob orchestration 为 📋 unsupported。OPStack matrix 行 #13 为 **explicit 深审**，当前实现不满足 isthmus-design B10 / AC #12。
