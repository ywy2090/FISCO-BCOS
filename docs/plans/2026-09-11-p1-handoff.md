## 5. 环境陷阱清单（照抄用，别再踩）

- `engine/test/CMakeLists.txt` 用 **configure 期 `GLOB_RECURSE`**：新增测试文件后必须 `cmake -B build -S .` 才会被纳入。
- Boost `--run_test` **不吃逗号分隔**（会 `Test setup error: no test cases matching filter`）；用单值/单通配。
- 套件名写错 = 0 例 = 假绿；一律用 `--list_content` 计数（基线 as-of `4e0d2c893`：engine 294 / block 142 / exec 123 / scheduler 37 / receipt 26 / bcos-evm 173 / tool 111 / ledger 234 / rpc 313 / tars 136；`OpEngineImportFcuTest` 30、`OpEngineApiVersionsTest` 16）。
- Boost 成功串是 `*** No errors detected`，**包含子串 `errors detected`**——任何「判红」逻辑都别用它。
- op-geth 评审树脏（纯注释），行号必须 `git show`。
- Go 构建实际走 **1.24**（两棵 pin 树 `go.mod` 要 1.24；本机 1.23.4 靠 `GOTOOLCHAIN=auto` 下载，需网络）。
- 语料 `opstack-executor/tests/t8n` 是**指向外部仓的 symlink**；本仓不追踪 generator 与生成物。
- stock macOS `/bin/bash` 3.2 无 `mapfile`；用 `while IFS= read -r`。
- 另一个会话（`deep-reorg` worktree）可能同时在跑构建——看到构建进程先确认是不是自己的。
- 后台 agent 的 **transcript 落盘很晚**，目录里只有 `metadata.json` 不能判定它死了；存活判据用「目标文件 mtime 新鲜度 + 是否有构建进程」。
